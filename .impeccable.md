# nxyz.art — design context for agents

Aligned with the studio README and `../nxyz-studio-design-system/` where the canonical brand brief lives. Tokens: `styles/tokens.css`. Fonts: `lib/fonts.ts` (Space Grotesk + JetBrains Mono).

## Design Context

### Users

- **Primary:** Creative directors, product leads, and collaborators evaluating motion, systems work, and shipped software — often arriving from referrals, writing, or social.
- **Secondary:** Peers and press skimming for craft signals and studio POV.
- **Context:** Short sessions, high scan speed, low tolerance for generic “startup landing” patterns. Many users will use **⌘K / Ctrl+K** to jump; the command bar is first-class navigation.
- **Job to be done:** Quickly understand *what the studio makes*, *what’s shipping*, and *where to go next* (selected work vs software vs contact).

### Brand Personality

- **Three words:** Editorial · precise · warm-trustworthy  
- **Voice:** Confident but not loud; “slow correspondence” energy — craft over hype. İstanbul-based, internationally legible.
- **Emotion:** Calm competence and curiosity, not urgency or FOMO.
- **Explicitly not:** Generic AI-SaaS chrome (cyan-on-dark, glass stacks, hero metrics), interchangeable card grids, or decorative mono walls. Mono is for **catalog labels, indices, and data** — human explanations use **sans**.

### Aesthetic Direction

- **Visual tone:** Editorial / magazine index meets light instrument panel: clear hierarchy, one violet accent, tinted neutrals (no pure #000/#fff as large fields).
- **Theme:** Light-first with a considered dark mode (`globals.css` + tokens); accent and ink flip for contrast on inverse surfaces (correspondence, footer).
- **References (in-repo):** Section headers (INDEX · N), filmstrip/marquee rhythm, wordmark, periodic “disciplines” table — these are signature blocks; new work should feel like the same publication.
- **Anti-references:** Dashboard widgets, gradient text for “impact,” stock illustration heroes, symmetrical three-column feature grids.

### Design Principles

1. **Typography does the work** — Use the modular scale and `clamp()` where appropriate; hierarchy beats decoration. Prefer one strong typographic move over many small effects.
2. **One accent, many neutrals** — Violet (`--accent` family) signals interactivity and emphasis; do not introduce competing primaries without a brief change.
3. **Explain the machine** — Dense UI (marquees, strips, ⌘K) gets **plain-language hints** and `aria-describedby` where needed; insider shorthand alone is not enough.
4. **Motion is optional** — Honor `prefers-reduced-motion`; auto-scroll pauses on drag/wheel; no bounce/elastic easing; prefer transform/opacity for deliberate motion.
5. **Shipped vs story** — **Software/products** and **client/studio work** are different stories; differentiate blocks (background, labels, copy) so the archive reads clearly.
6. **Economy of chrome** — Sidebars and grids should feel intentional, not duplicated “admin panels.” Differentiate stacked patterns when they appear twice on one view.

### Accessibility & inclusion

- Target **WCAG AA** for text on surfaces (tokens tuned for this on base and inverse).
- **Reduced motion** and **reduced data** paths exist for previews (e.g. BrowserFrame); extend the same thinking to new motion or embeds.
- Focus: visible `focus-visible` rings (accent); skip link remains above sticky nav.
